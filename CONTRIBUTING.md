# Contributing (Planning Draft)

SitePulse is in planning. Please open an issue before a large implementation PR.

- Read project rules and the master tracker first.
- Changes should reference an issue, phase, and acceptance criterion.
- Add tests/docs for code changes.
- Avoid secrets and unnecessary dependencies.
- Use descriptive commits and include actual test output in PR descriptions.
- Security findings should be reported privately, not as public exploit steps.

A full contribution guide will be finalized before Phase 05 release.
